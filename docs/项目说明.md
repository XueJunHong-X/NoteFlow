# NoteFlow 项目说明

> 面向「学习生活」场景的手写笔记智能整理工具

---

## 一、项目简介

**一句话**：把用手写笔记的学生从「整理」这件事里解放出来——文件丢进文件夹，笔记自己变成可检索、可关联、可渲染的知识库条目。

**问题**：iPad 手写笔记和纸笔笔记有三个硬伤，且都不是「写得慢」造成的：

1. 只能看，不能搜。手写内容不在任何全文检索里，期末复习只能一页页翻。
2. 不能连。高等数学的「导数」和工程制图的「公差」在脑子里是通的，在笔记里是死的。
3. 整理成本高。把一学期的手写笔记整理成电子笔记，通常要几小时到几天，多数人直接放弃。

市面上的手写 OCR 给的是「一段文字墙」：标题层级没了、荧光笔重点没了、箭头关系没了。
学生拿到的仍然是一堆需要重新组织的文字——只是把「抄」换成了「复制粘贴再排版」。

**NoteFlow 做的不是转文字，是转结构**：识别时同步还原标题层级、重点标记、箭头语义，
直接输出 Obsidian 可用的 Markdown（含 LaTeX 公式），并在归档时自动完成课程分类、
索引生成、思维导图与跨笔记双链。

**目标用户**：以 iPad 手写为主、用 Obsidian 或类似工具管理知识的大学生。

**交付形态**：Windows 桌面应用（Python + tkinter，PyInstaller 打包为单目录 exe）。
双击即用，不需要安装 Python、不需要打开浏览器、不需要注册或登录任何网站；
不依赖云盘 API，把笔记库指向 OneDrive 等同步目录即天然获得云端同步。
真实识别需要联网调用多模态模型；没有密钥时可用离线示例模式完整看一遍链路。

## 二、技术方案

### 2.1 处理链路

```
投递（图片 / PDF / .goodnotes）
   ↓ loader：统一拆页（PDF 200dpi 栅格化；有文字层且非整页图时优先抽文字）
   ↓ preprocessor：EXIF 转正 → 背景除法去阴影 → 投影法倾斜矫正 → CLAHE 增强
   ↓ recognizer：多模态模型（OpenAI 兼容接口）→ 严格 JSON 结构
   ↓ markdown_gen：标题层级 / 重点加粗 / LaTeX 公式 / 关联概念
   ↓ organizer：课程推断 → 归档 → 课程索引 → 课程总览
   ↓ linker：概念提取 → 别名归一 → 打分 → 正文注入双链
   ↓ mindmap_gen：标题层级 → Mermaid mindmap
   → Obsidian vault
```

### 2.2 关键实现

**① 识别结果是一份契约，不是一段文本**

模型被要求只输出一个固定结构的 JSON：`title / sections(heading, level, content, highlights, subsections) / arrows / tags`。
其中：

- `level` 最多 3 层，标题只在标题位置出现一次（禁止在正文首行重复）；
- `highlights` 只从 `content` 里摘重点，不能替代正文，避免「只留重点、丢掉细节」；
- 公式强制 LaTeX（`$...$` 行内、`$$...$$` 独立成行），Obsidian 原生渲染；
- `arrows` 只在箭头明确连接两个名词性概念时输出，变量、数字、括号片段不能作为端点。

**② 预处理只做三件真正影响识别率的事**

去阴影用「背景估计 + 除法」处理光照不均；纠偏用水平投影方差搜索最优小角度旋转
（文字行越水平，投影方差越大）；增强用 CLAHE 拉出铅笔与淡墨的对比。
不做复杂去噪、不做二值化——过度处理反而会吃掉细笔画。

**③ 归档是一个收口，不是散落各处**

所有跨笔记相关的动作（课程推断、索引刷新、总览刷新、双链规划、导图生成）都收在
`organizer.archive_note` 一处。好处是：在线识别与离线重建（`--rebuild-vault`）两条入口
自动共享同一套逻辑，不会出现「这条路径有索引、那条路径没有」的不一致。

**④ 双链「有目标才成链」**

概念只从标题（权重 3）与各级 heading（权重 2）提取，经过长度、LaTeX 片段、罗马数字、
结构标签（例3/图2）、话语标记（同理/综上）、泛词（方法/系统）多道过滤；
链接目标必须是 vault 内真实存在的笔记，找不到就保持纯文本。
再加三道闸：笔记总数阈值（冷启动少于 3 篇不连）、权重阈值（默认 3）、单篇上限（默认 4）。
结果：全 vault 悬空链接为 0，误链靠「正文落地校验」压掉（概念写法必须真的出现在本篇正文里）。

**⑤ 失败只降级，不中断**

单页识别失败、索引刷新失败、导图生成失败，都只告警并写 `failures.jsonl`（一行一条 JSON），
队列继续往下走。识别 JSON 解析失败时先自动追加一次纠错请求，仍失败则退化为
「原文 + 待校对」，保证不产出空笔记、不卡住整条流水线。

### 2.3 技术栈

| 模块 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.10+（开发用 3.12） | 生态完整，学生可二次修改 |
| 监听 | watchdog | 加文件稳定检测，避免读到写了一半的文件 |
| 预处理 | OpenCV + Pillow | 头文件开销小，headless 无 GUI 依赖 |
| 识别 | 多模态大模型（OpenAI 兼容接口，实测 `qwen3-vl-plus`） | 中文连笔 + 数学公式 + 版面语义一体完成，无需自训 |
| 文档拆页 | PyMuPDF | 无需外部 poppler，PDF 文字层与栅格化都能做 |
| 知识库 | Obsidian（原生 Markdown + Mermaid + 双链） | 不需要自建前端，产物即最终形态 |

### 2.4 桌面化与打包

- 界面用 Python 自带 tkinter，不引入 PySide/Electron 之类额外 GUI 依赖，装完依赖即可跑；
- PyInstaller `--onedir --windowed`：启动快、比单文件版更少被杀软误报；exe 读取的配置在
  `%APPDATA%\NoteFlow\config.json`，**密钥不进仓库、不打进包**（Windows 下经 DPAPI 按当前用户加密后保存）；
- 图像/PDF 相关模块是运行时才 import 的，PyInstaller 静态分析看不到，构建脚本显式补
  `cv2`、`pymupdf`、`watchdog.observers.winapi`、`src.*` 等隐藏依赖；
- 打包后裁掉运行时用不到的体积（OpenCV 视频编解码库、PyMuPDF 版面 ONNX 模型），
  整目录从 388 MB 降到 **200 MB**；
- 只把 `tests/sample_images/*.png` 两张合成样例打进包，`real/` 下的个人笔记一律排除；
- 保留 `--cli`（透传原有命令行参数）与 `--selftest`（无界面自检）两个入口，
  桌面化不牺牲已有能力。

### 2.5 数据流向与隐私

- 真实识别时，**每页的图片**（或 PDF 该页的文字）会发送到你自己配置的云端多模态模型接口；
  除此之外，密钥、其他笔记、目录结构、使用记录都不会附带发出；
- 所有拆页、预处理、归档、索引、思维导图都在本机完成，产物只写到你选的 vault 目录；
- 密钥只存本机 `%APPDATA%\NoteFlow\config.json`（Windows 下经 DPAPI 按当前用户加密，换账户或换机器无法解密；也可用环境变量），不进仓库、不打进 exe，界面默认打码；
- 离线示例模式全程不联网，适合评审在没有密钥的环境里看完整链路。


实测：冷启动到窗口可见 1.15 s；`--selftest` 端到端 4.37 s（含解释器加载，流水线本身 0.23 s）；
图片型 PDF 经 exe 跑通全链路。

## 三、创新点

1. **结构化识别，而非文字转写**
   把「版面语义」（标题层级、重点标记、箭头关系）当作一等公民写进识别契约，
   输出直接可用，省掉二次整理这一步。这是与普通手写 OCR 最大的差异。

2. **桌面形态 + 零配置可验收**
   双击 exe 即可用，不需要装 Python、开浏览器或登录；没有密钥时界面明确标注「离线示例模式 ·
   非真实识别」，仍然能把链路、产物、目录结构完整跑一遍。评审不用申请账号也能看到真实产物。

3. **一条不断裂的自动化链路**
   从文件出现到索引/导图/双链刷新，全程无人工触发第二步；单点失败跳过并留痕，
   符合「丢进去就行」的使用直觉，而不是「先跑这个脚本、再跑那个脚本」。

4. **边际成本为 0 的知识库化**
   课程索引、课程总览、Mermaid 思维导图、跨笔记双链全部本地计算，**0 次额外模型调用**；
   只有「识别」这一步花额度，且按页计费、可用 `--max-pages` 截断。

5. **对齐真实笔记缺陷的工程化兜底**
   不是 demo 级实现：针对中文手写笔记实测暴露的问题——「解/例/注」被误判为标题、
   装饰箭头被臆测成概念关系、`[[n]] → [[(n−1)]]` 这类无意义双链——都做了可验证的规则兜底
   （单字标题降级、端点过滤、悬空链接归零）。

```text

```

## 六、诚实边界

- `.goodnotes` 目前只读得到内嵌的课件截图/翻拍照，**读不到矢量手写笔迹**；
  对用户的标准建议是「从 GoodNotes 导出 PDF 再处理」。这条写在 README 的「真实限制」里，
  不靠模糊表述掩盖。
- `.goodnotes` 页序是提取顺序，不等于真实页码，已在 frontmatter 中用 `page_note` 标注。
- 跨笔记双链只认字面：`高阶导数` 与 `常用函数的 n 阶导数公式` 不会自动互连，需要别名表补充。
- 版面语义仍由模型判断，极少数续写句可能被判为标题（已做降级），装饰性箭头可能被误读（已做过滤）。
- **桌面版不是「完全离线可用」**：界面处理是离线的，但真实识别必须联网调用多模态模型；
  没有网络或没有密钥时只能用离线示例看链路，界面上不会把它说成真实识别。
- **exe 有体积代价**：整目录约 200 MB（图像库 + PDF 渲染 + GUI 运行时），压缩后约 100 MB；
  必须整个目录一起分发，不能只拷 exe。
- exe 未做代码签名，部分机器会弹 SmartScreen「未知发布者」提示；首次启动比后续慢（杀软扫描）。
- 对外材料只使用仓库内的合成样例图，个人真实笔记（`tests/sample_images/real/`）不进入任何提交物，
  也不会被打进安装包（构建脚本只收集 `*.png`）。
